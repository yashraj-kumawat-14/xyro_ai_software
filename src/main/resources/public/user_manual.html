FEATURES & INSTRUCTIONS
◉
SECTION 01

Speaking & Wake Word Activation

XYRO can use wake word detection and speech recognition when these features are enabled and configured.

  • Wake words: The previous configuration uses David or Xyro.
  • How to speak: Say the wake word followed by your question, for example, "Xyro, where is St. Mary School?"
  • Recognition variations: Phonetic variations such as Zyro, Xero, Zairo, or Syro may be recognized depending on the speech recognition setup.
  • Voice orb: The interface displays an animated orb. Its visual states can be connected to listening, processing, and speaking when those features are implemented.
ⓘ

The current web interface supports typed chat. Microphone input and speech playback require separate implementation.

⚙
SECTION 02

Engine Settings & Password Lock

Use the Settings area to configure the assistant's engines and preferences when those controls are available.

  • Password protection: The previous application design specified protected settings and deletion actions. Verify the current implementation before relying on this protection.
  • Speech recognition (STT): The previous design included Android System Recognizer and offline Parakeet GGUF options.
  • AI response engine: The previous design included a local llama.cpp model and Google Gemini cloud API.
  • Text-to-speech (TTS): The previous design included Piper and system voices.
ⓘ

In the current desktop version, chat uses your local Qwen model through Java, JNI, and llama.cpp. The Settings button is not yet functional.

◎
SECTION 03

Face Recognition

The previous design specified InsightFace with the Buffalo_L model and ArcFace face embeddings.

  • Register Face: Intended for capturing face images and associating them with a person's name.
  • Face Recognize: Intended for scanning a face with a camera and matching it against registered people.
  • Saved faces gallery: The previous design included a gallery for reviewing registered face images.
  • Deletion controls: The previous design specified password protection for deleting saved faces.
ⓘ

Face registration, recognition, gallery management, and deletion protection are not yet connected to the current desktop web interface.

↻
SECTION 04

GitHub OTA Commands Sync

The previous application design specified synchronizing voice commands from a GitHub-hosted JSON file without requiring a full application package update.

  • Open Settings when command synchronization is available.
  • Enter the raw GitHub URL for the relevant commands.json file.
  • Use the sync action to retrieve updated commands and reload them into the application.
ⓘ

OTA command synchronization is documented from the previous design and is not yet implemented in the current desktop interface.

✧
SECTION 05

Local Offline LLM

XYRO's current desktop backend runs a local language model through llama.cpp using a native JNI library.

  • Current model: Qwen 2.5 1.5B Instruct, Q4_K_M GGUF.
  • Inference: Java sends the prompt to the native C++ inference library and receives the generated response.
  • Chat endpoint: The web interface sends messages to POST /api/chat.
  • Model file: The current desktop setup loads the GGUF file from the configured local model path at server startup.
  • Internet access: Local model inference itself does not require cloud inference. Other application features may still require network access.
ⓘ

Keep the model file and required native libraries available on the computer running the Java server.
